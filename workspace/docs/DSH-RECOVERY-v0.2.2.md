# v0.2.2 · 两小时执行与聊天内接续

2026-11-09。用户要求代码任务超时改为2小时，并修正超时后在同频输入“继续修正”没有反馈的问题。本次明确授权恢复当前已中断任务；保留其独立副本改动，不重新派发为另一任务。实现前冻结以下范围与验收。

## 超时与安全边界

- installed worker默认`runTimeoutMs=7200000`（2小时）；新绑定和当前本机配置同步更新。分类独立`classificationTimeoutMs`默认`min(runTimeoutMs,120000)`，版本检查仍最多30秒，不为启动调用模型。
- 超时后仍终止本次拥有的CLI进程树并核验退出，释放自己的租约。错误提供`kind=timeout`和可信的`processTreeStopped`供消息区分；未证实退出时不能允许新的worker。中断仍是uncertain，不自动重做，不清空原始记录。原生runner的running字段不能被当作进程存活证明；新增本次bridge终态记录，不改旧历史日志。

## 在线等待与明确控制

- installed+auto启用聊天恢复。任务进入started/uncertain/routing_failed时，桥接保留在线、暂停新任务派发、只处理恢复控制；重启同样进入等待状态，不因旧异常退出监听或自动重跑。其他executor/旧mention兼容原有行为。
- managed transport仍为listening，增加`taskStatus: paused/ready/running`和待处理事件ID等安全元数据；当前有暂停任务并不等于连接离线。停止脚本仍可正常停止空闲的暂停监听，不需要杀worker。
- 仅绑定群、白名单人类成员的新消息可以操作该群暂停的任务，机器人和其他群不可恢复。继续前重新核对原任务作者/群授权。精确命令支持“继续”“继续修正”“继续任务”“恢复任务”“重试任务”，可带`@机器人名`和末尾标点；“继续讨论”、引用或夹带其他指令不作为控制。
- “取消任务”“跳过任务”仅放弃暂停任务等待，不撤销或删除代码；确认后可接新任务。本轮不增加执行中实时取消或自由文本接管。
- 暂停时普通同群授权消息收到一次简短提示，说明可发送“继续修正”或“取消任务”；不再静默无反应。未暂停时的明确恢复命令回复“当前没有暂停任务”，不交给分类器生成新任务。

## 持久接续与去重

- `Bridge`提供`supportsChatRecovery`、`isPaused()`和`taskStatus()`；`poll()`在暂停时处理恢复队列，不启动普通新任务。`prepareChatRecovery()`只规范化started为uncertain并发送幂等恢复说明，不执行模型；bridge入口启动时用它替代无参数resolveCurrent的阻断。显式CLI RetryEvent/SkipEvent仍保留。
- 继续命令先持久保存授权的接续意图/命令ID、尝试编号和恢复游标，再进入pending执行。使用原逻辑和原生会话，向worker明确先核对已有diff/已完成步骤、保留修改、接续未完工作；不reset、不用新会话冒充恢复。恢复会话缺失或准备失败重新暂停并提示，不无限预模型重试。
- main cursor不越过未完成原任务。恢复扫描使用独立recoveryCursor，已消费控制事件持久去重；成功后普通poll不把这些命令再分类为代码任务。接纳一次恢复时对当前可见消息建立边界，之前重复的继续命令不能在本次再次失败后自动触发下一次恢复。
- 各尝试的失败/继续提示使用稳定且区分尝试的幂等client_id，回复确认丢失可重发，不能多次启动worker。恢复命令也受成员和群过滤，不能通过聊天更换工作目录、权限或认证。
- 老v0.2.1的当前uncertain状态保留，迁移后读取原任务之后的未处理控制消息；用户已经在软件发送的“继续修正”可以接续一次。未来重启仍不自行执行未授权恢复。若原生映射/所有者锁有问题则明确暂停，不删除锁或换新会话。

## 实施与验收

根代理负责bridge循环/managed状态、配置默认值与本机激活；core代理只改core/recovery模块与单测；executor代理只改installed executor与相关测试；集成测试代理只改隔离进程测试。主检出和DSH蓝色主题副本的文件责任分离，禁止覆盖后者未提交改动。

1. 小时限假CLI测试timeout结构化原因/已停止子树，2小时配置只检查参数，不实际等待2小时。原版session映射与cwd互斥回归通过。
2. 实际Node+动态HTTP+fake CLI验证超时后在线等待、同群授权继续一次、原会话接续/保留已有结果、禁止机器人/跨群/未授权控制、取消继续后续任务、控制幂等/重复旧指令不重做。
3. restarted uncertain/routing_failed保持transport就绪且worker零调用，明确恢复后才执行；继续失败仍在线等待，普通消息有指引。
4. 常规Python/Node/编排回归；真实本机配置改为2小时，启动后找到软件已发送的继续消息并确认原native session实际恢复。真实接续只一次，不为失败无限重试。
5. 用户说明写入桥接README、恢复入口和HANDOFF；代码/脱敏结果commit、新v0.2.2 annotated tag、push并查询远端。私有状态/聊天/原始日志和蓝色主题待审查改动不混入本轮运行时功能提交。
