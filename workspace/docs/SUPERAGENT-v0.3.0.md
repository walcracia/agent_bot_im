# v0.3.0 · Super-agent 完整协调层

2026-11-09，编码前设计。用户要求补齐前次对照中所有未实现和部分实现项。本设计覆盖 v0.2 的单任务串行限制，保留现有 IM 成员隔离、两小时 worker 预算、旧状态/原会话保护与 Git 交接原则。依据为用户给出的 Super-agent 文章及官方研究原型，不将原型视作可直接部署的成品。

## 验收矩阵

1. 两级准入与常驻 Router：IM 事件持久接纳后推进读取游标；独立路由循环按小批量识别新任务、补充、叫停和状态询问。模型不得改写群、成员、项目、认证和交付策略。Router 不执行编码。
2. 并行 Worker：每项任务独立 ID、原生会话、Git worktree 和分支；不同任务可同时执行，限制最大并行数。同一任务不重入，同一目录跨实例互斥。两个受阻任务同时执行时，第三条控制指令仍可被接收和处理。
3. Thread 与连续性：IM 消息/任务和 GitHub PR/评审/CI 各有稳定引用；显式任务引用直接路由，模糊补充由 Router 判断，不能随意作用于另一项任务。已绑定 PR 的事件直达原任务；跨来源沿同一 task 保留上下文。
4. Inline/Spill：近期摘要、目标、任务关系内联；完整消息、结果与证据存持久引用图，通过受鉴权、限定授权范围的读取工具逐跳取回。不得只截断而没有续读入口。
5. 双工交互：接收循环不等待 worker。运行中补充先持久化并确认接收，原生支持时注入；否则确认终止本次拥有进程后，保留文件和原会话接续新指令。停止可作用于运行、排队或暂停任务；不撤销已有代码。多个活跃任务时必须有明确任务 ID 或成功的语义归属，不盲选。
6. Watchdog：独立进程、独立只读模型会话，依据目标、真实活动、差异与测试证据识别无效循环/偏航/停滞；有界纠偏或暂停并告知人员。还检查控制器心跳和来源故障。主程序崩溃不使监督回路一并消失。自动恢复只针对可证明安全的调度/传输，不重做不确定工具副作用。
7. 存算与环境：控制器任务/引用/游标/Outbox 位于持久状态卷，计算可重启；执行端通过鉴权守护进程提供固定项目环境。支持将 DSH 放在控制侧、通过远程工具访问原地环境；也保留本机原生 DSH 路线。远端连接使用 TLS 或明确的本机回环测试。设备离线任务保留排队，恢复后按原任务继续。
8. GitHub 闭环：配置绑定的目标仓库，运行可信配置的验收命令，核对差异并提交到任务分支、推送和幂等创建/更新 PR；收取评审/CI/关闭事件并反馈到原 IM。合并由可信本机策略控制，开启自动合并时必须检查指定 head、审查与必需检查；不把未知/排队检查算成功。构建发布只执行可信配置命令，不执行聊天提供的 shell。
9. 恢复与低打扰：Outbox 先保存再发送，稳定键去重；重启保留任务、输入、原 session 和 worktree，结果重发不重复模型工作。以简短接收/需要行动/结果为主要群输出，不回传原始推理。管理员诊断按需读取。
10. 主动静默核查：可信proactive策略及独立验证交付都启用后，未明确交办的具体缺陷可speculate；直接私聊/@或明确请求仍为可见任务。以原baseCommit的真实变更和可信测试为交付门槛，无变化/未复现/失败保持静默，公开PR或被人明确接手后才按普通任务反馈。规范与验证见SUPER-PROACTIVE-v0.3.0.md。

用户随后明确选择“可信测试通过后自动合并”：可信mergePolicy=verified-tests可不依赖独立GitHub评审账号，必须在固定repo/base/task分支执行可信验收、确认源码/索引/HEAD未被测试改变，并以exact head合并；有配置的远端检查仍必须通过。Workers仍并行，交付串行并同步/复验最新base；新任务从核验的远端base创建，不移动开发者主HEAD。已合并任务的新修正建立带父引用的后续任务；未合并而已关闭的任务只有明确恢复才沿原副本/会话重新打开原PR，不能丢掉未提交工作。

## 模块和职责

- `super-coordinator.mjs`：调度状态机、Thread 订阅、并发、输入与动作、Outbox；只由串行事务队列写账本。
- `super-context.mjs`：持久引用图、受限 Inline/Spill 与按需召回。
- `super-router.mjs`：只读跨任务决策，普通讨论批处理，不运行代码。
- `super-agent.mjs`：IM、GitHub、HTTP 控制/召回入口和独立监督进程的运行集成；保留旧桥接入口兼容。
- `super-worker.mjs`、`super-daemon.mjs`：任务独立副本/会话、原生 DSH、取消与远程执行端，具体协议见对应设计。
- `super-github.mjs`：受信任仓库的 PR/评审/CI 来源和验证后交付。
- `super-watchdog.mjs`：外部的语义监督回路，单独状态与有限干预。

控制器默认本机回环，HTTP 使用环境变量中的控制码，不在 URL、示例或 Git 中放凭据。聊天仅为资料；任何任务路径、命令、目标仓库和额外权限均来自受信任配置。worker 的独立副本是变更隔离，不宣称是 OS 沙箱。

## 迁移与停止

新模式使用独立 `superAgent` 配置及状态路径，不覆盖 v0.2 任务账本。已有暂停任务必须保留并显式接续或迁移，不能换新任务冒充恢复。旧启动配置继续可用；完成新模式验收后再为本机绑定启用。停止接纳新任务，持久保存输入/结果，再按拥有关系关闭 worker；未证明退出不释放其工作目录租约。

## 验证与交付

- 临时 Git 仓库、隔离 HTTP/数据库和假 CLI 验证并行、运行中输入/取消、权限、跨来源、崩溃恢复、Outbox 丢确认、错误模型输出、离线重连和监督纠偏。原测试必须继续通过。
- 本轮真实模型验收显式启用，预算最多 6 个只读分类/监督会话、2 个微型编码任务及其明确的中途补充；记录实际 session 数、文件差异及独立测试，不以模拟测试替代真实模型证据。
- 真实 GitHub 操作仅限本项目任务分支和验收 PR，验证完成后记录其状态；不改其他仓库。腾讯实际部署需要操作者提供主机连接信息，资料未提供时只记录可复现部署与本机验证，不宣称云端已经常驻。
- 完成后更新 API/DESIGN/DECISIONS/PROCESS/TESTING/HANDOFF、恢复入口与环境状态；明确清单提交、annotated tag、push、远端核验。客户端如有变化重新构建 Windows 包并核验。

## 真实验收预算调整

首轮2个原生会话已完成并行编码与补充后的独立验证，但输入回执断言失败。真实日志证明原生 user/message 的 data 本身是消息，初版插件按 data.message 读取而漏记回执；同时原生 followup 是下一轮，下一步干预需用 steer。保留首轮失败证据，先用已存事件做离线回归；根协调明确限定增加一次原A会话的接续turn来验证修正，不新建第三个native session，不重做B，不无限试模型。只读Router/监督预算仍最多6个会话。

原A接续已通过真实 next-step 注入及原生消费序号/持久回执匹配。为实际覆盖计算与执行环境分离，根另行明确限定1个新 remote-tools 原生会话、1次turn、5分钟：控制侧空目录运行DSH，本机独立daemon保存代码与运行固定验收命令，实际MCP读写与独立检查。不重做A/B、不部署云端。总预算因此为3个原生worker会话、原A额外1个接续turn；实际只读Router及Watchdog各1次。

静默主动性另明确限定1个只读分类会话、2分钟、两消息批处理、不运行worker；实际返回普通缺陷speculate、明确请求new，零重试。只读实际总计Router两会话（含此项）及Watchdog一会话，仍在最多6会话预算内。
