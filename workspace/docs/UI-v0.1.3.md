# v0.1.3 · 蓝色主题

2026-11-09。用户要求把当前界面改为以蓝色为主色调，更新样式/设计令牌中的主色与强调色，使登录页与主界面配色一致，清除旧主色残留；布局、文案和功能保持不变，并检查文字与控件对比度。

## 范围

- 只调整颜色与设计令牌，以及品牌图标 SVG 的配色；不改 DOM 结构、交互、文案、字号、间距、圆角、阴影、动效和响应式布局。
- 登录页、聊天主界面、成员/设置弹窗、附件菜单、空状态、错误/重试、上传进度、键盘焦点统一使用同一套蓝色语义。
- 旧绿色主色名称和值一并移除，包括令牌名、CSS 引用与 logo 中的绿色；语义错误红、警告琥珀保留。头像的暖色/玫瑰色仅作成员区分，不属于主色。
- 在线状态点改用主色蓝，仍由 `title`/`aria-label` 和文字状态表达，不依赖颜色单独传达。

## 色彩策略

深海军蓝承担导航与品牌纵深，明亮蓝色承担操作与焦点，浅蓝灰承担页面、会话和自身消息表面；正文用蓝黑，次要文字用冷灰。避免把同一高饱和蓝铺满大面积，主色只用于按钮、链接、未读、选中、进度和焦点。

| 角色 | 令牌 | 值 |
| --- | --- | --- |
| 正文 | `--ink` | `#1f2a3b` |
| 次要文字 | `--muted` | `#56657a` |
| 主色 | `--primary` | `#2563eb` |
| 主色悬停 | `--primary-hover` | `#1d4ed8` |
| 主色按下 | `--primary-pressed` | `#1e40af` |
| 深色导航/品牌 | `--primary-deep` | `#102a4c` |
| 强调色（未读/选中/进度） | `--accent` | `#0b6fd8` |

蓝色调中性表面：`--paper:#fbfcff`、`--chat:#f3f7fd`、`--surface:#f8faff`、`--surface-soft:#eef3fb`、`--surface-hover:#e7eefb`、`--surface-selected:#dfe9fb`、`--surface-pressed:#d5e3f8`；边框 `--line:#dde5f0`、输入边界 `--field-line:#71829b`。自身消息 `--own-bubble:#dbe8ff`，媒体/文件表面改为冷灰蓝，深色播放底改为深蓝黑。

## 文件

- `client/tokens.css`：新增/重写颜色令牌，`--green*` / `--accent-hover` / `--accent-pressed` 改为 `--primary*`，新增 `--accent`；头像 `--avatar-olive*` 改为 `--avatar-indigo*`。
- `client/styles.css`：只替换令牌引用及强调色落点（未读、选中、进度、复选框），不移动选择器或布局属性。
- `client/logo.svg`：保留图形，蓝色底、白气泡、深蓝描边。
- `workspace/docs/UI-v0.1.3.md`、`DESIGN.md`、`PROCESS.md`、`HANDOFF.md`：记录范围、实际测试和限制。

## 验收标准

1. 1280×860 与 960×680 下，登录页、聊天页、成员/设置、附件菜单整体呈蓝色主题，无旧绿主色或绿色调表面残留。
2. 旧主色十六进制值与 `--green*` 引用在客户端源码中不存在；主按钮、导航、未读、选中、焦点和自身消息均来自新令牌。
3. 对比度：正文/次要文字 ≥4.5:1；按钮文字、未读白字、导航文字与焦点环 ≥3:1（普通文字目标 4.5:1）；控件边界 ≥3:1。用计算值而非肉眼判断。
4. 现有真实浏览器流程（登录、错误恢复、群聊/私聊、消息分组、时间键盘、IME、附件四类媒体、拖放、重试、重连、XSS、管理员创建助手、退出）保持通过；现有布局、文案和功能不变。
5. 产物截图和报告写入忽略目录；不调用真实 DSH 模型、不部署生产。

## 测试方法

- 运行既有 `environment/scripts/verify-ui-v0.1.2.py` 做全流程回归，确认行为未回退。
- 运行新增 `environment/scripts/verify-ui-theme.py`：临时隔离服务 + 真实 Chrome，读取登录页与主界面的 computed style，检查蓝色角色、旧色残留和关键对比度，输出 1280×860 / 960×680 截图。
- 运行 Python 单元测试、客户端/桌面 JavaScript 语法检查与 PowerShell 解析检查（与本次改动相关的最小集合）。
- 人工查看批量截图；发现颜色/可读性问题集中修正一次，再做确认轮。
