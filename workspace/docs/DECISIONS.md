# 决策记录

## ADR-011：可信测试自动合并与版本顺序

用户明确选择“可信测试通过后自动合并”。本机启用mergePolicy=verified-tests，无需独立评审账号；配置的远端检查仍必需通过，默认review策略不变。新任务核验origin/base后创建独立副本，交付串行，同步最新base并复验，按exact head合并。可信版本清单在交付层统一递增，空任务不生成版本；发布固定合并commit。已合并任务的新需求建立有父引用的后续任务；关闭未合并PR只在明确继续时重开，不换原会话或清理代码。

## ADR-010：Super-agent职责分离与真实回执

2026-11-09。按用户“全部补全”授权新增独立协调层，保留单进程IM，另将消息接纳/Router/Worker/监督/交付分开。每任务独立worktree、session和输入账本；接收不等待执行；确认原生next-step消费才记已送达。真实集成发现followup与steer语义不同、user/message data结构不同，保留失败后以实际事件/回执修正，不能靠模拟通过宣称原生接入成功。

## ADR-011：可证明的恢复与发布

任务副作用不确定时暂停，禁止靠删worker锁或换会话恢复。只有已死亡的控制器/监督进程租约且相应原生终态可证明时才自动恢复；明确停机优先于恢复。Windows恢复使用当前用户已保存IM绑定并更新真实进程登记。GitHub只关联绑定PR，过期head/批准/成功CI不重启编码；自动修复有界。自动合并和发布由可信配置授权，不从聊天更改。发布固定已合并commit、独立checkout、锁定命令及产物，已发布tag/asset不覆盖。

## ADR-002：单服务 SQLite + Electron

面向小团队与个人轻量服务器，优先减少 Redis/Postgres/独立对象存储等部署依赖。消息实时层单进程，明确未来横向扩容须引入跨进程 pub/sub 与数据库迁移。Electron 提供 Windows 便携包，Python 只存在服务器。

## ADR-003：100 MB 定义与媒体渲染

用户写 <100M，取明确的十进制阈值：最大接受 99,999,999 字节。只按检测的安全媒体类型 inline，其他类型下载。音视频兼容取决于 Chromium codec，不添加高资源服务端转码。

## ADR-004：DSH 按官方协议验证

微信链接不能由 web 工具直接读取（2026-11-07，非重试错误）。继续通过文章/官方仓库研究，不把假定 HTTP 接口标成已兼容。设计先确定有身份、成员范围、游标和幂等的 IM 事件接口。

后续：用户指定既有公开仓库walcracia/agent_bot_im并完成CLI设备授权。已改本地后续提交身份，设计及v0.1.0已真实上传。OAuth缺workflow权限使首轮含自动化文件的push被拒绝，改为deploy中的可选模板，不扩大权限；只重写尚未上传的本代理提交，未force push。

## ADR-006：界面只表达用户操作

v0.1.1依用户红框与/impeccable要求删除四块登录说明，进一步移除普通界面的SDK/DSH/监听/令牌等术语、宣传眉题和页脚。原有布局/色彩保留；图标以title/aria-label补足语义，必要后果只在生成连接码等具体操作中出现。详情默认关闭，字段称账号/昵称/团队地址。以UI-v0.1.1规格覆盖初版解释性设计。

## ADR-007：有限真实本地模型测试

使用已有共享Ollama模型和单独SDK-minimal profile，不接触其他项目密钥、不改共享服务、不调付费API。只进行预先计划的两次小文本调用。SDK精确答复通过；真实IM回复多@dsh前缀，传输成功、严格格式失败，按停止条件不重试美化结果。复杂工具工作不因此宣称完成验收。

## ADR-008：本机IM与DSH联合就绪

2026-11-09。用户要求监听随启动绑定，默认start调整为IM+已配置DSH联合就绪，ServerOnly仅用于首次bootstrap/排障。助手码用Windows当前用户DPAPI保存到Git忽略的本机JSON，替代每次重输；不复制DSH认证。Node以唯一实例状态/停止文件实现Windows无强杀的优雅停止，先完成当前事件再停IM；已有游标/异常任务/旧锁保护继续保留。独立代码副本和群/成员授权不因便利启动而放宽。此轮不注册系统服务、不做崩溃自动重试。

## ADR-009：暂停任务仍保留恢复通道

2026-11-09。实际主题任务在5分钟后被终止，旧进程退出令群里的继续指令无人接收。按用户要求将代码任务上限改为2小时，并将执行故障与消息连接分开：auto/installed保留监听，只有同群授权的明确继续才使用原会话接续；取消只结束等待、不回滚代码。控制游标与任务游标分离、持久去重、接纳前重验权限，防止旧重复消息在再次失败后自动重做。

Windows状态文件在实测中出现EPERM原子替换失败，增加有限退避并每次重新检查实例owner；失败发布链允许下一次重试。任务账本先持久化，后续显示状态发布错误只写本机诊断，不能打断已准备的worker。初始连接就绪仍严格校验；不放松原会话、工作目录租约或进程退出证明。
