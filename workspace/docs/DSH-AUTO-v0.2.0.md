# v0.2.0 · 团队讨论自动触发本机 DSH

当前恢复行为由`DSH-RECOVERY-v0.2.2.md`覆盖本文件的“失败停止监听/只在本机恢复”部分：默认worker两小时，任务暂停时连接保留，同群授权明确发送“继续修正”接续原native会话，未收到控制不自动重做。

2026-11-08。用户指定当前 agent-bot-im 为首个验收项目，触发模式选择“普通讨论也自动识别任务”。文章 [Super-agent 设计探索](https://mp.weixin.qq.com/s/zoS7GlReWPhfCjENGxXCdg) 已重新读取正文；它是架构探索，官方公开仓库亦为研究原型。本轮落实单项目的实际编码闭环，不宣称实现完整并行 Router/Worker 系统。

## 已确认范围

- 同频继续承担团队消息与附件；现有消息成员权限、聊天和派任务者白名单不变。
- 新增可选择的 `triggerMode: auto`，旧配置默认 mention 模式保持兼容。自动模式从同一授权聊天读取有界近期消息，只让授权成员的新消息成为派任务依据。
- 语义识别使用只读 DSH 调用，输出严格结构化的 ignore/code_task 决策；聊天取消、暂不实施、已解决或普通闲聊不执行。分类失败时不启动代码 worker，不将失败冒充 ignore 成功。
- worker 使用本机已安装 DSH 的 headless CLI 与其存储认证；不下载第二套 Desktop、不复制密钥、不操纵现有桌面会话。SDK executor 继续保留供旧配置使用。
- 原逻辑 session ID 与原生 session-... ID 另外持久化映射；同一目录恢复，异常保持 uncertain，需要操作者判断，不自动重做已可能产生副作用的工作。
- 自动模式新实例默认从当前消息位置开始，不把旧群聊重放成新任务；同群近期历史仍可作为新任务上下文。只有可信本机配置明确设置processExistingMessages才处理既有积压，断点续接不丢已接任务。
- 一个桥接实例绑定一个项目副本，当前为 agent-bot-im 的隔离 Git worktree。任务串行执行，群聊接收不受影响。目录、执行权限、CLI、认证来源由本机可信配置确定，不接受聊天改写。
- 回传简短任务状态和最终结果，保留原有幂等回复。需要真实 diff/指定测试证据，不把模型自述当作验收通过。不会因识别普通聊天而自动合并或上线。

## 实施文件与职责

- 主代理：bridge 自动识别路由、core 集成、配置与入口、集成验收/交接/发布。
- executor 子代理：仅新增 installed-headless executor 与配套便携 PowerShell runner/认证插件 patch，及其隔离协议测试；不修改 core/router。
- 验收子代理：只负责不调用模型的自动识别/上下文边界回归脚本与测试，先对契约设计，随后集成；不修改产品 core。

## 验收和停止条件

1. 旧服务器/桥接/界面基础检查不回退；普通闲聊、机器人消息、未授权会话/成员不启动代码执行。
2. 同群有限上下文，当前事件以后的消息不提前注入，其他群消息不进入上下文；决策校验严格，空白/畸形输出不执行；相同事件回复丢失只重发结果，不重复修改。
3. 真实模型验收在当前仓库的隔离副本与明确标注的微型代码夹具中进行：聊天无需@，模型识别任务、修改真实文件、运行指定小测试、群里读到结果，操作者另核对diff和测试退出码。夹具缺陷不是生产缺陷，不合入生产代码。
4. 真实验证限制为预定少量分类/执行调用，不无限重试或下载模型；认证、版本、额度或任务失败时保留脱敏错误与本地证据，暂停实际激活，不虚称已工作。
5. 常驻正式监听需要操作者的真实同频账号/聊天绑定。没有配置时提供本机交互式启动入口；不擅自创建团队成员或从其他项目提取凭证。

设计与实现完成后按新版本 commit/tag/push；部署配置、原始聊天/模型日志、任务工作副本和认证不进 Git。生产 UI 不增加架构说明。
