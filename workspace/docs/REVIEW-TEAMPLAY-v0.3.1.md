# v0.3.1：Super-agent 核对与同频TeamPlay更名

日期：2026-11-10。范围在实现前冻结。

## 用户范围

对照 DeepSeek Harness 团队《Super-agent 设计探索：迈向更自主的 Agent 系统》与当前源码，明确符合程度，把设计和业务流程直接写入根 README；产品显示名称统一为 **同频TeamPlay**。

本轮不实现审查发现的能力缺口，不扩大为界面重设计、真实模型实验、正式监听或腾讯部署。原文是研究探索，不把概念核对称为官方认证，也不把历史模型实验称为本轮结果。

## 设计选择

- 根 README 是当前产品、团队/IM/DSH/代码仓库协作和能力边界的总入口；保留各模块详细设计和历史验收，不覆盖旧版本事实。
- 使用“连续、高效、主动、持久”及 Router/Worker、运行中输入、引用召回、外部监督逐项核对。结论以源码、常规测试、历史真实验收和当前运行四种证据分别表达。
- 登录品牌、页面/窗口标题、图标替代文字、Windows 产品属性和当前使用说明改为精确名称“同频TeamPlay”；蓝色主题、图标、布局和操作保持现有规格。
- npm 包名、TeamRelay.exe/输出目录、TEAMRELAY_PROFILE、localStorage、协议标识和旧 Electron app.setName('同频') 保留兼容。后者用于沿用既有用户目录；Windows 可见名称由页面/窗口及 PE 产品属性提供，不引入资料迁移。
- 产品元数据统一为 0.3.1（服务 VERSION、桌面 package/lock、桥接 package/lock）。依赖锁中的依赖条目不变。
- Windows 包构建到新的版本目录，不覆盖旧包；完整包通过 Release 交付，大文件不进源码 Git。

## 验收标准

1. README 包含判断结论、模块关系图、正常业务流程、运行中补充/取消/恢复、主动核查、GitHub 交付/发布、部署方式、权限边界和证据等级；明确上下文预算、Router候选、补充附件、顺序风险及异机验收限制。
2. 当前可见品牌统一，无旧营销/技术说明重新进入 UI；内部兼容标识和历史报告不进行机械全局替换。
3. JS 语法和现有完整常规验证通过；不调用真实模型。浏览器在1280×860、960×680各看一次登录及主界面，集中处理必要问题，最多一轮修正。
4. 0.3.1 Windows 实际构建；ASAR 白名单及六个源码文件字节一致、包版本/PE名称、ZIP清单/CRC/SHA256核验。原生窗口和人工登录未经执行不能记作通过。
5. 更新 PROCESS/DECISIONS/TESTING/HANDOFF、RESTORE 与 state；明确本机状态、历史证据与剩余工作。按明确文件清单 commit、新建 annotated v0.3.1、push并核对远端；Release资产确认后才称已上传。

## 分工

主代理：文档核对、README、服务/桥接元数据、集成验收与Git交付。文章代理：只读原文与官方原型。执行审查代理：只读核对实际运行语义和缺口。更名代理：仅 client/、desktop/、workspace/package*.json，更改显示名称与版本，保留兼容标识。
