# v0.5.1：每轮打包、日志复验、会话可见与max思考

2026-11-23，实施前设计。用户本轮要求：每轮完成都打包；公司QA日志可以恢复测试；核查Pi/Hermes桌面缺少测试记录；DSH DeepSeek思考强度设max。本文件覆盖此前暂停QA及使用首档/off思考的要求，仅改变用户明确指定的模型参数，原插件取证/提示/报告业务流程不改。

## 实施范围

- 每个验证通过的产品迭代生成新版本Windows便携目录、ZIP与SHA清单，核对ASAR/PE/manifest及实际启动。账号、原生模型凭据、日志、聊天、运行库不入包。客户端与后台部署边界写清，不把前端包冒称包含DSH/Pi/Hermes及服务器。上传源码tag及对应Release资产，不移动已发布版本。
- 按实际原生存储查Pi/Hermes真实会话，解释桌面列表过滤/索引差异。修复新会话的原生登记/存放方式，已有真实会话只按官方原生索引规范补登记，保留备份；不伪造历史、不重复模型制造“记录”。需明确会话属于独立工作目录，桌面能找到原native ID及原始内容。
- DSH业务Worker、Router、QA direct和显式回归使用可信max配置，核对实际模型支持及请求/回执；不能只改显示字样或静默降回off。需要调整输出配置时以本轮明确max要求为准，不恢复会话调用/阅读额度。
- 实查公司网络和授权QA接口，再以已选历史Bug的同附件、全时段、空现象、mid复验完整原插件流程。聊天只回原结论和一个完整报告，用量在下载。阶段中不因缺时间/缺描述另加宿主诊断或追逐预设答案；必要材料直接询问用户。

## 验收

1. 新native请求实际max；原取证/system/user保持，结果由skill原文机械提取。
2. 真实QA读取→聊天触发/Router→下载整包→原插件解析/DSH→原结论与下载完成，材料/模型/native/文件/hash证据落忽略目录。
3. Pi/Hermes历史与新会话原ID可定位，原生桌面列表或其同一读取接口核验，不拿项目自己的receipt充当桌面历史。
4. 相关协议/流程回归及项目必需检查通过，Windows包实际产物和启动通过；设计/过程/接续/脱敏验收、commit、新annotated tag、Release资产和远端回执齐全。

## 集成补核

在业务/Router/QA wrapper已实测max后，进一步核对InstalledHeadless旧基础入口，发现其未消费harness.modelSelection。最小补丁在每次非version调用的自有run目录生成max模型patch，先于原wrapper patches，不改后者顺序/正文/守卫；version继续零模型。覆盖将来重新启用的旧代码Worker及Watchdog，不因补配置而启动这些模块。
