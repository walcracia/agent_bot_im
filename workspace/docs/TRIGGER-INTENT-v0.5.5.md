# v0.5.5 自然问句与 QA 分流

2026-11-25，先设计后实现。用户示例“T13JVP最近没有bug么”应获得最新缺陷情况，不启动历史日志重分析。当前监听已退出且游标停在该消息之前；Windows 2004 事件和心跳 clone OOM 时间相邻，证据支持整机提交内存耗尽，不支持断言业务账本泄漏。

## 流程

授权成员消息 → Trigger 保留原消息 → 当前聊天已跟踪项目内的 QA 意图识别 → 可信绑定验证 → 查询或原日志 Worker → 持久 Outbox → 原聊天。

固定跟踪、编号分析和任务控制保持优先。自然 QA 候选由独立 QaIntentRouter 识别：recent_issues、analysis_status、analyse_issue、clarify、not_qa。明确查询采用确定性快速判断，剩余候选使用现有只读 Qwen4 Max / High classifier。模型只选择已登记项目/同聊天任务、编号与查询天数，不取得账号或执行权限，不生成路径/命令，不撰写 QA 查询结果。泛业务消息继续既有 BusinessRouter。

仅该聊天已启用且有权限的绑定可选。省略项目时只有一个绑定才默认；多匹配、缺编号或含糊指代直接提问。查询默认近7天，支持最近N天1–365（尚未支持的日历范围澄清）；这是查询参数验证，不是模型或日志阅读额度。否定疑问“没有bug么”属于查询；“不要分析”不能触发执行。自然分析必须原句明确请求分析并给出该项目编号，礼貌委托问句也可表达执行请求；模型猜测、原因或进度问题不能升级为执行。分析附带日期不适用查询范围限制。固定控制取消/继续规则保持，不由问题查询自动重做旧失败任务。

## 只读业务结果

executeQaQuery({adapter,binding,request:{kind,days,issueNo,taskId},tasks,pollRecord,now}) 返回 {text,data}。实时查询完整分页的 QA 数据，区分近期新增、当前未解决、最后成功巡检和本地分析任务；只返回简短中文文字。显示时间范围和计数口径，无时区 QA 创建时间按可信查询配置 Asia/Shanghai 解释（不推断故障时间）。无日期单列，查询失败不答“没有 Bug”，不把缓存当本次成功。无附件下载、无日志模型调用、无业务任务创建。

## 监听开销

心跳单次执行，避免上一次未完成又排队；存标量内存观测。协调器心跳只复制活性元数据，历史任务、图和报告保持引用且不修改；无新消息且无游标/权限变化的空轮询不复制/重写历史。保留原事务锁和原子写，禁止删历史、锁或杀其他项目进程。现有 start 验证真实 PID 后恢复本次已退出监听，不将 stale ready 当在线；不承诺能免疫整机资源耗尽。

## 验收与交付

1. 单测覆盖真实示例、否定、项目隔离、查询/进度/分析区别、坏分类结果、分页失败、未知时间，以及心跳非重叠/历史不被修改。
2. 新监听实际消费用户原消息并在原聊天回答最新 QA；真实自然查询不创建分析任务。显式自然分析接入原编号请求，不走通用 Agent 猜测。
3. 按 QA-MVP-v0.5.4，以当前源重新触发一次真实原插件 Skill/Qwen4High 分析，取得原结论+完整 TXT 并认证下载；旧成功不替代。
4. 常规验证通过后交付 v0.5.5 Windows 便携包/ZIP/SHA，实际 EXE 验证、源码新 annotated tag 与 GitHub Release 资产核对。设计、失败、结果和恢复点同步记录；账号/原始聊天/日志只留忽略目录。
